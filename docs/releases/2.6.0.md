# AniView 2.6.0

Release candidate: `2.6.0+36`, stable channel. Awaiting release-content approval before push or CI.

## Release notes

- Improved Android TV controls: distinct Sub/Dub focus and selection, with episode order beside Play. The existing in-player server picker is available when multiple servers are returned.
- Customize soft subtitles: size, color, background, shadow/outline, font, bold text and vertical position, with a preview and reset.
- Optional Latest episodes home section shows recently aired anime across the catalog, with pagination and retry. Airing dates do not guarantee availability on a streaming source.
- Optional season grouping follows prequel/sequel links while keeping each entry's episode list and tracking separate.
- Optional fallback to Sub when an episode has no Dub servers. The next episode tries the preferred audio again; playback history records the actual language. Network errors do not change language.
- KickAssAnime and AnimeStream sources; filler labels and skipping; Jellyfin audio selection and progress sync; Jellyseerr requests.
- In-app desktop updates, playback/subtitle/quality fixes, safer download storage and recovery, desktop search retry, and portrait phone browsing.

Latest episodes, season grouping and Sub fallback default off. Enable them in Settings.

## First-launch experience

The exact overview copy is in `lib/changelog.dart`. “What's new in 2.6.0” appears once per version and remains accessible through Settings → About. Its actions are Buy me a coffee, Join Discord, and Got it; TV shows only Got it.

The existing subscription survey follows the overview when analytics is configured and enabled, and this installation has no saved stable survey state. Stable and beta survey states are separate. Existing stable answers and dismissals are not reset.

Title: **Would you pay US$1 per month to use AniView?**

Body: A subscription would support development and let me dedicate more time to maintaining the embedded servers, fixing bugs, and releasing new features faster—while keeping the app polished and reliable.

Choices:

- Yes, I’d be more than happy to pay.
- Keep the app free. I’ll try to donate more often.
- A subscription would be a dealbreaker for me.

Footer: Nothing is changing yet—your feedback will help me decide.

The only visible action is Submit answer, enabled after selection. Tapping outside does not dismiss the survey; Back can dismiss it while not sending. Failed submission retains the selection and offers retry through the same button. Successful submission shows: “Thanks for sharing your thoughts. Your feedback helps shape AniView’s future.” No subscription or payment is introduced.

## Analytics and release workflow

- Rybbit production host: `https://rybbit.clouderp.co.tz`; events use `/api/track`. App default and local defines agree. The host responded HTTP 200 during preparation.
- GitHub's `DART_DEFINES` secret is write-only and cannot be inspected. CI's existing packaging guard requires this production host and a nonempty site ID. Live event delivery is not proven by the host availability check or mocked tests.
- Push to `main` automatically starts CI. Packaging additionally needs a successful native-verification artifact for the exact candidate commit, covering Android phone, Android TV, iOS, Linux, macOS and Windows. See `docs/native-verification.md`.
- Dispatch stable packaging with `beta=false` and the native-verification run ID.
- Publishing the stable GitHub release automatically posts its notes to Discord with `@everyone`. CI itself does not publish the release.
- Android APK and Linux AppImage builds are local steps, not outputs of the current CI package matrix. Their device verification and artifact provenance must be resolved before publishing those assets.
