BUG-01 (`Sites.all()` isolates and time-limits the extension host), BUG-02 (an update is loaded from a staged file before it replaces the

## Findings vetted but not yet planned

Opened and confirmed in the code (see `file:line`); waiting for the maintainer to choose.

- **BUG-01 (HIGH, S)** One failing or slow extension takes the built-in sources down with it:
  `lib/sources.dart:30-36` builds `Sites.all()` as `[...await load(), ...await ExtensionSource.installed()]` with no
  isolation, and `installed()` (`lib/sources.dart:662`) throws if the Android channel errors.
- **BUG-02 (HIGH, S)** Updating an extension can destroy the working copy: `android/.../Extensions.kt:121` calls
  `uninstall(...)` (deletes the old APK) *before* the new one is loaded, and `:129` deletes the new one on failure, leaving
  nothing. Fix: install to a temporary name, load, then swap.
- **BUG-03 (MED, S)** Extension episodes lose information: `lib/sources.dart:701` passes `title: ''`, and
  `Extensions.kt:73-81` rebuilds a bare `SAnime`/`SEpisode`; 18 of 246 usable extensions never set an episode number, so
  every episode is `-1`, and `lib/details.dart:273,362` key selections and downloads by `episode.number`.
- **TEST-01 (HIGH, M)** None of the new code has tests: `lib/extensions.dart` (repo parsing, `ExtensionInfo.supported`),
  `ExtensionSource.match`, `Picking`/`PickingScope`, `watchedShare`, `TvRemote`. Plan these together with committing the tree.
- **SEC-01 (MED confidence, S, trade-off)** `android/app/src/main/AndroidManifest.xml` sets no `allowBackup`/data-extraction
  rules, so Android's default backup copies `FlutterSharedPreferences` — the AniList bearer token (`lib/anilist.dart:130`)
  and the paired TVs' AES keys — to cloud backup. Fix is all-or-nothing (settings and history are in the same file), so it
  is a maintainer decision.
- **PERF-01 (MED, S)** `Extensions.kt:204-214` resolves every video of an episode concurrently with no cap; a hoster with
  dozens of qualities fires dozens of simultaneous requests at one site. Bound it (e.g. 4 at a time).

## Direction (options, not problems)

- **Extension settings**: ~226 of the 252 repo extensions implement `ConfigurableAnimeSource`, and `setupPreferenceScreen` is
  never called, so server-style extensions (Jellyfin, Stremio, Torrentio, debrid) can't be configured. Rendering their
  preference screens natively is the biggest compatibility lever.
- **Cloudflare for extensions**: `NetworkHelper.kt` has no challenge solver while `lib/cloudflare.dart` already solves them for the
  built-in sites; extensions hitting a Cloudflare page just fail with 403.

## Findings considered and rejected

- AniList token in plain `SharedPreferences` (`lib/anilist.dart:104`): app-private storage on Android; encrypting it would not
  stop in-process code. The real exposure is backup (SEC-01).
- Extension signing key taken from the same repo that serves the APKs (`lib/extensions.dart`, `Extensions.kt` `install`): this is
  Aniyomi's own trust model, the key is pinned at repo-add time, and each install shows a "runs code inside AniView" consent dialog.
- `HlsProxy` lists never evicted (`lib/hls_proxy.dart:15`): already marked `ponytail:` as a deliberate, session-bounded choice.
- Remote-press replay after the TV app restarts (`lib/pairing.dart` `_lastPress`): needs a LAN attacker holding a captured sealed
  press, and the worst case is a key press within a 5-minute window.
- Update download URL not host-checked (`lib/settings.dart` `_UpdateDownload`): Android refuses to install an update signed with a
  different key, so a wrong URL cannot replace the app.
- Very large files (`details.dart` 2.5k, `player.dart` 2.2k, `home.dart` 2.0k, `ui.dart` 1.9k lines): real, but splitting them with
  widget-level tests only is risky and nothing is currently blocked by it. Revisit after TEST-01.
